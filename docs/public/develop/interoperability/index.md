# Interoperability

If you are evaluating an existing project or vendor ecosystem, use the
task-oriented [Migrate Into truST](../../migrate/index.md) section first. The
ecosystem pages have canonical URLs under `Migrate` so migration readers stay in
one part of the docs.

## Pick The Ecosystem

- [PLCopen](../../migrate/plcopen.md)
- [OpenPLC](../../migrate/openplc.md)
- [CODESYS and TwinCAT](../../migrate/codesys-twincat.md)
- [Siemens](../../migrate/siemens.md)
- [Mitsubishi](../../migrate/mitsubishi.md)
- [Vendor Libraries](../../migrate/vendor-libraries.md)

## Rule Of Thumb

- Start with [Migrate Into truST](../../migrate/index.md) if you are still
  deciding the migration route.
- Start with PLCopen if the question is about XML import/export or portability.
- Start with CODESYS and TwinCAT if the question is about day-to-day
  Beckhoff/CODESYS-style authoring.
- Start with Siemens or Mitsubishi when you need concrete migration or style
  guidance for those ecosystems.
- Use Vendor Libraries when the source project depends on libraries that truST
  does not ship directly.
