# Changelog

This page renders the repository changelog directly so release notes stay
inside the searchable docs surface.

Use it when you need the public release narrative for a version, not when you
need the implementation plan behind a change. For upgrade planning, pair this
page with [Version History](reference/version-history.md) and the relevant
Operate page for the surface you are changing.

Success means you can answer which version introduced a public behavior, which
docs page explains the behavior today, and whether a change is user-facing
enough to affect release notes.

If you are deciding whether to upgrade, read the release notes first, then open
the affected Start, Operate, Migrate, or Reference page for the current workflow.
