# Run8 installation failure diagnosis

Read-only independent review. Installation failed inside flash write_image, before verify_image or planned UART acquisition. No runtime fixture result exists for this physical attempt. All software and source-bound linked evidence remains as recorded.

Retained logs show sector0 and4–7 erase completed. First ELF segment was written; upper segment then aborted. OpenOCD reported unexpected reset and recovered double-fault. State: RCC_CSR0x04000000 (PINRSTF, no IWDGRSTF), IWDG PR0/RLR0xfff reset defaults, DBGMCU watchdog halt-freeze0x1800, CFSR0x00010000 UNDEFINSTR, HFSR0x40000000 FORCED. SYSTICK/NVIC enable/pending zero. These do not support attributing the reset to the watchdog. Reset cause remains unresolved.

Disassembly matches the stacked PC0x0806ef68 to __primask_r, called from _critical_section_1_0_acquire at0x0801a146 with returnLR0x0801a14b. Firmware main calls that immediately at0x08010246. Lower stacked returns0x08014d2d and0x08010059 match main/Reset. Therefore partial new-firmware startup executed after the unexpected reset. The CPACR arguments are stale from reset startup, not the faulting instruction. The upper helper and HardFault address0x08072108 were not fully programmed; this explains undefined-instruction then double-fault. It is not an engine/stack-guard defect and is not physical fixture execution evidence.

OpenOCD default STM32F4 script runs the flash algorithm in SRAM0x20000000 with32KiB work area, sets DBGMCU0x1800 on examine, and reset-init configures64MHz PLL plus2 flash wait states. Upstream cortex_m.c reports external reset when unexpected DHCSR.S_RESET_ST is observed; that label alone does not identify its electrical/software cause. Primary source: https://github.com/openocd-org/openocd/blob/master/src/target/cortex_m.c (cortex_m_poll_one). Flash driver source: https://github.com/openocd-org/openocd/blob/master/src/flash/nor/stm32f2x.c .

Recommended installation protection, not a claimed trigger fix: enable reset vector catch during erase/program/verification so an unexpected reset is caught before partial firmware startup; retain/read back DEMCR and capture verbose installer evidence. Programming upper code before final sector0/vector publication would additionally avoid exposing a new vector before its target code exists. Preserve failed attempt and checkpoints, and distinguish any further explicitly authorized installation attempt. No source edit, firmware execution, reset or programming command was run by this reviewer.
